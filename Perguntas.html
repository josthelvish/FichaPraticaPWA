1 - O que são operações de “Commit”, “Push” e “Pop” efetuadas num repositório?

  • Commit - é o ato de guardar e registar no repositório local, as alterações associadas e um respetivo comentário;
  • Push - é o ato de enviar para o repositório remoto todas as alterações locais previamente "commitadas";
  • Pop - é o ato de recuperar código que havia sido guardado na stack de local stash;

2 – Quais são as vantagens de usar Branchs num repositório git?

As principais vantagens de usar branchs no Git são que poder isolar o nosso código em diferentes estágios (ex: código pronto a produção num branch, e código em desenvolvimento noutro) e assim trabalhar em paralelo com múltiplos intervenientes. Também permite correção de bugs diretamente num branch que se encontre em produção. Outra utilização fundamental, na minha opinião, é a de submeter branchs isolados de código a peer review, via Pull Requests, antes de os juntar à branch principal.

3 – Nos Merges de conteúdos resultantes de um “Pop” podem resultar em conflitos. Em que consistem e como podem ser resolvidos esses conflitos?

Conflitos ocorrem quando a junção de duas partes do texto (ex: alterações locais (fonteA) e um pedaço de código stashed(fonteB)) indicam que a mesma parte do texto foi editada em cada uma das versões a juntar. Nesse ponto o git indica a existência de um conflito, permitindo o utilizador indicar a sua resolução. A resolução passa pelo utilizador indicar quais as partes da fonteA e fonteB que serão mantidas e quais as que serão descartadas.

4 – “Clone” e “Fork” são formas diferentes de replicar um repositório Git. Quais as diferenças entre eles?

  1. O clone cria uma cópia local de um repositório remoto.
  2. O fork cria uma cópia do mesmo repositório, sendo a diferença o local onde vai ficar essa réplica do repositório.

Assim sendo com um clone temos uma ligação ao repositório original e, caso tenhamos permissões de edição, podemos por isso propor alterações ao mesmo, ao passo que o Fork já permite alterar o conteúdo que copiou na origem, sem necessitar de permissões pois neste caso o repositório é seu, mas não submeter o mesmo no repositório de origem.
